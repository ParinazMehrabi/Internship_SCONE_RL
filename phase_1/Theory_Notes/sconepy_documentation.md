# Getting Started with SconePy
# 1. Introduction

## What is SCONE?

SCONE (**Simulation CONtrol Environment**) is an open-source software platform for biomechanical simulation and optimization of musculoskeletal systems.

It is widely used in biomechanics and movement science to simulate human locomotion, optimize controllers, and analyze musculoskeletal models.

SCONE provides an intuitive graphical interface called **SCONE Studio**, where users can:

- Load musculoskeletal models.
- Configure simulation parameters.
- Run simulations.
- Visualize movements.
- Analyze simulation results.
- Optimize controllers.

Most users begin by interacting with SCONE through its graphical interface.

---

# 2. What is SconePy?

**SconePy** is the official Python API for SCONE.

Instead of controlling simulations manually through SCONE Studio, SconePy allows users to control every part of a simulation directly from Python.

Its main purpose is to make SCONE programmable and easily integrated with modern machine learning and Reinforcement Learning (RL) frameworks.

> "A Python API for SCONE, designed and streamlined for Reinforcement Learning applications with biomechanical simulations."

In other words, SconePy acts as a communication layer between Python and the SCONE simulation engine.

---

# 3. Why was SconePy developed?

Running a few simulations manually through SCONE Studio is simple.

However, many research applications require thousands of simulations.

- Reinforcement Learning for example


Performing these tasks manually would be extremely time-consuming.

Instead, Python programs can automatically:

- Load models
- Run simulations
- Read simulation outputs
- Modify controllers
- Save results
- Repeat the process thousands of times

This automation is exactly what SconePy provides.

---

# 4. SCONE Studio vs. SconePy


```text
        SCONE Studio
             │
             ▼
      SCONE Simulation Engine
             ▲
             │
         SconePy API
             ▲
             │
          Python Code
```

Both SCONE Studio and SconePy communicate with the same simulation engine.

The difference is only **how the user interacts with the engine**.

# 5. Main Features of SconePy

According to the official SCONE documentation, SconePy provides three major features.

---

## 5.1 Access to Sensors and Actuators

SconePy provides direct access to biomechanical sensors and actuators using NumPy arrays.

### Sensors

Sensors provide information about the current state of the model.

Examples include:

- Muscle force
- Muscle length
- Muscle velocity
- Joint positions
- Center of mass
- Body orientation

Example:

```python
forces = model.muscle_force_array()
```

This function returns the force generated by every muscle as a NumPy array.

---

### Actuators

Actuators are the components that receive control commands.

In musculoskeletal simulations, actuators usually represent muscle excitations.

Example:

```python
model.set_actuator_inputs(inputs)
```

This command sends excitation values to the muscles.

---

## 5.2 Neural Delay Support

Real biological systems do not react instantly.

There is always a delay between:

- sensing information,
- processing it by the nervous system,
- activating muscles.

SconePy supports these neural delays automatically.

Example:

```python
model.delayed_muscle_force_array()
```

Instead of reading the current muscle force, this function returns the delayed muscle force, resulting in more realistic neuromuscular simulations.

---

## 5.3 Easy Reward Shaping

One of the most important parts of Reinforcement Learning is defining the reward function.

SconePy provides easy access to simulation data required for reward calculation.

Examples:

```python
model.com_pos()
```

Returns the center of mass.

```python
model.time()
```

Returns the current simulation time.

```python
model.body("pelvis")
```

Returns information about the pelvis.

These quantities can be combined to define rewards such as:

- Walking forward
- Maintaining balance
- Minimizing energy consumption
- Reaching a target speed

# 8. What does the example do?

The official example demonstrates a complete simulation workflow.

The program performs the following steps:

1. Import SconePy.
2. Load a musculoskeletal model.
3. Initialize the simulation state.
4. Read muscle sensor values.
5. Compute muscle excitations.
6. Send excitations to the model.
7. Advance the simulation.
8. Store the simulation results.
9. Measure simulation performance.

# 9. SconePy imortance for RL?

In Reinforcement Learning, an agent repeatedly interacts with an environment.

The interaction cycle is:

```text
Agent
   │
   │ Action
   ▼
SconePy
   │
   ▼
SCONE Simulation
   │
   │ Observation + Reward
   ▼
Agent
```

During every simulation step:

1. The RL agent computes an action.
2. SconePy sends this action to SCONE.
3. SCONE simulates the biomechanical model.
4. Sensor values are returned.
5. A reward is calculated.
6. The agent learns from the result.

Without SconePy, this interaction would require manually running simulations in SCONE Studio, making Reinforcement Learning impractical.
